## 当前实现与复用边界

- 活跃入口：life-weave.html，加载 Three.js 0.160.1、life-weave-core.js、loom-model.js、weave-journey.js。原生脚本，无 React / GSAP，无需迁移框架。
- loom-model.js 使用程序化几何建立木质织机，导出 LoomScene，共享模型、相机、Renderer、手柄、布料、打纬器及踏板。独立 loom-model.html 和已有 GLB 保留。
- 坐标 Y 向上，正面 +Z。手柄轴沿 X，中心 (1.04, 1.23, -0.76)。模型有连续布面几何和 UV；当前交互另加 1.3 × 0.78 的平面于 (0, 0.72, 0.985)，使用 1000 × 600 CanvasTexture。
- 当前单相机整体→手柄→布面切换；转满一圈后播种，再以定时器运行 18 代。当前五种元素集齐才显示结果，退出会清空。
- life-weave-core.js 是有限边界 B3/S23。五种种子及颜色身份保留，出生颜色按邻居多数决定，平票取较小编号。不存在独立相生相克算法，禁止杜撰。
- 动效是 requestAnimationFrame 与相机插值，已有减少动态效果适配、DPR 上限和 WebGL 错误提示。旧 life-weave.js/css 非活跃原型，不删除。

## 状态与事件

阶段为 landing → approach → weaving → result。ENTER / APPROACH_DONE 对应镜头开始和完成；RETURN_HOME 保留创作；CONTINUE 恢复编织；RESET 是唯一主动清空事件。

- wheelAngle：累计机械角度，可反转。
- effectiveAngle：历史最大正向角度，只增不减。反转有机械反馈；重新前进到之前位置之后才继续织造，避免同一圆弧反复晃动刷进度。
- segments：每圈 element 和已织角度，不存模型对象。首次默认木（0），后续按木火土金水循环，整圈边界允许手动选择及重复选择；部分圈锁定元素，避免改写已织片段。
- dragging：仅输入状态；不承担暂停或自动增长。松手不会推进。
- summary：圈数、完整圈数、当前圈比例、是否有作品、已实际织入元素顺序。整圈完成时 currentProgress 为 0，UI 可根据 completedTurns 的增加显示完成反馈，不能误判为空作品。

ROTATE 接受单次归一化角度增量（[-π, π]），支持键盘小步输入；指针端用 deltaAngle 处理跨越 ±π。连续的极小浮点误差在整圈边界容差内吸附，不能用此容差自动补全可见缺口。

FINISH 支持零圈和半圈；零圈 result 必须展示空状态，不能导出虚假图案。自动继续跨入下一圈不增加空白元素记录。

serialize / restore 仅支持该状态契约的 JSON 往返，拒绝损坏数据并恢复初始态；不恢复拖动或中断的镜头过渡。**尚未接入 localStorage，也不包括生命网格/纹理数据，不能宣称已实现完整作品恢复。**

## 风险与验收

- 双视口：Pointer 坐标必须相对于手柄视口；注意 CSS 像素、DPR、scissor 底部原点和顶部 DOM 原点差异。窗口变化及过渡时不能误拖。
- 双相机共享模型，不能重复移动模型/手柄 pivot。渲染两次可能增加阴影开销；按需更新阴影并控制 DPR。
- 布料：复用现有表面，检查木架遮挡、深度冲突和 UV 方向；不能仅增长一个悬浮面板。
- 算法：改变触发节奏不是替换 B3/S23。渲染帧率不得影响代数，松手不能继续演化。
- 旧浏览器测试要求反转扣进度、集齐五种和退出清空；它们描述旧行为，Phase 2 起逐项改成新验收标准，不应直接删除全部回归测试。
